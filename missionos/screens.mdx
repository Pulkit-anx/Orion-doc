MissionOS specifies **47 screens** across seven categories. This page covers all of them: what each
one is for, what it does, and where its values come from.

<Note>
  **Each screen has two independent states, and they answer different questions.**

  **Interface** — does the screen exist and run? *Implemented*, *Designed*, or *Specified, deferred*.

  **Data** — where do its values come from? *Live* from hardware, *Prototype values*, *Planned*
  hardware, or produced *On-device*.

  A screen can be fully implemented and still show prototype values, because MissionOS reads every
  reading from one shared model and a screen never talks to a sensor itself. That separation is the
  design — see [the data model](/missionos/data-model).
</Note>

<Note>
  The pictures are **design renders** at 1:1 device scale, not photographs. They were drawn against
  an earlier control layout, so the hint bar naming physical controls has been removed from each
  one. Screens whose render contradicts current behaviour are listed without a picture.
</Note>

### Boot and self-test

Splash screen and power-on checks.

**Interface** Implemented · **Data** Prototype values

The splash is built. Most self-test results are placeholders, so the boot sequence is not evidence that hardware works.

### First-run wizard

A short guided setup when ORION starts for the first time.

**Interface** Implemented · **Data** Prototype values

Runs at every start, because settings are not saved yet.

### Home

A clock face and swipeable cards. Swipe up for the launcher, down for Quick Settings.

**Interface** Implemented · **Data** Prototype values

Navigation works on the prototype. The clock, date and card values are prototype values, because there is no clock driver and no environmental or positioning hardware.

### Launcher

Seven categories of built-in screens and a User Apps tab.

**Interface** Implemented · **Data** On-device

Verified on the prototype, including the User Apps tab, which lists apps installed through the User App Platform.

### Quick Settings

An overlay for radios, torch, sound, haptics and brightness.

**Interface** Implemented · **Data** Prototype values

Opens with a swipe down from Home. The toggles change interface state only; they do not control radios or other hardware yet.

### Settings

Device, display, input and system preferences.

**Interface** Implemented · **Data** Prototype values

Settings are not saved and reset at every restart.

### Power and battery

Battery level, power source and power-save mode.

**Interface** Implemented · **Data** Prototype values

Shows prototype battery values. The prototype has no battery measurement, and ORION's rechargeable power system is part of the Rev02 concept.

### Files

Browse sessions, drawings and other stored data.

**Interface** Implemented · **Data** On-device

Reports on-device flash storage. microSD card support is planned for the Rev02 base unit and is not implemented.

### Alerts

Toasts, confirmation dialogs and critical full-screen alerts.

**Interface** Implemented · **Data** On-device

Alert presentation is built. The conditions that would raise real alerts, such as a low battery, are not measured yet.

### Charge face

A minimal face shown while charging or sleeping.

**Interface** Implemented · **Data** Prototype values

Shows a prototype charge state. Charging hardware is part of the Rev02 concept.

### System update

Check for and install firmware updates.

**Interface** Implemented · **Data** Prototype values

The screen exists. No firmware update mechanism is implemented.

### App Link

Pairing with a companion app.

**Interface** Specified, deferred · **Data** —

Not currently implemented. No companion app exists, and the launcher tile is disabled.

### Sensor Hub

Nine tiles summarising every instrument. Tap a tile to open it.

**Interface** Implemented · **Data** Live in part

The motion and sound tiles read live hardware. Temperature, humidity, pressure, air quality, altitude and heading are prototype values, and light sensing is not available on this prototype.

### Weather

Temperature, humidity and pressure with a short trend.

**Interface** Implemented · **Data** Prototype values

Prototype values and a synthetic trend line. Needs the Environmental module.

### Air Quality

A VOC-based air-quality index with Good, Moderate and Poor states.

**Interface** Implemented · **Data** Prototype values

Prototype values. Needs the Environmental module. The index is based on volatile organic compounds; it is not a particulate or health measurement.

### Altimeter

Pressure altitude and climb rate.

**Interface** Implemented · **Data** Prototype values

Prototype values. Needs the Environmental module. Pressure altitude differs from satellite-positioning altitude, and the screen says so.

### Compass

Heading, with a prompt to calibrate.

**Interface** Implemented · **Data** Prototype values

Prototype heading. The prototype's motion sensor has no magnetometer. Rev02 plans 9-axis motion sensing in the base unit.

### Level

Pitch and roll with a bubble level.

**Interface** Implemented · **Data** Live

Live tilt from the prototype's motion sensor.

### Motion Lab

Live acceleration traces, peak g-force and drop estimates.

**Interface** Implemented · **Data** Live

Live acceleration from the prototype's motion sensor.

### GPS

Fix status, coordinates, altitude, speed and satellite signal strength.

**Interface** Implemented · **Data** Prototype values

Prototype fix and coordinates. Satellite positioning is planned for the Rev02 base unit and is not fitted to the prototype.

### Light and Colour

Ambient light on a logarithmic scale, and colour capture.

**Interface** Implemented · **Data** Planned

Opened from Sensor Hub. The screen reads a light-sensor driver, but no light sensor is detected on the current prototype. Light and colour sensing belong to the planned Optical module.

### Sound Meter

Relative sound level with maximum and average.

**Interface** Implemented · **Data** Live

Opened from Sensor Hub. Reads a live, relative and uncalibrated level from a microphone wired to the prototype; it is not a calibrated sound level meter. The frequency bars shown in the design are not implemented. In Rev02, sound sensing belongs to the Audio I/O module.

### Data Logger

Choose sensors and an interval, then record a session.

**Interface** Designed · **Data** Planned

Designed, not implemented. Field Logging covers part of this flow today.

### Graph Viewer

Plot recorded sessions.

**Interface** Specified, deferred · **Data** —

Not currently implemented.

### ISS Tracker

Upcoming passes of the International Space Station.

**Interface** Implemented · **Data** Prototype values

Prototype pass list. Predicting passes needs orbital data and a position, and neither is available yet.

### Sun and Sky

Sunrise, sunset, day length, moon phase and a best window for outdoor solar charging.

**Interface** Implemented · **Data** Prototype values

Calculated by the firmware from a prototype location and time.

### Motion AI

Teach ORION motions and bind them to actions.

**Interface** Implemented · **Data** Prototype values

Prototype list of taught motions. On-device motion matching is designed, not implemented.

### Air Mouse

Use ORION as a Bluetooth LE pointer or presentation remote.

**Interface** Implemented · **Data** Prototype values

Prototype device list. Bluetooth LE is not used by the firmware yet.

### Stopwatch, timer and alarm

Stopwatch with laps, countdown timer and a daily alarm.

**Interface** Implemented · **Data** On-device

Stopwatch and timer run from the firmware's timer. The alarm follows the prototype clock until a real-time clock is implemented.

### Calculator

A four-function calculator.

**Interface** Implemented · **Data** On-device

Runs entirely in firmware.

### Torch

Turns the display into a light.

**Interface** Implemented · **Data** On-device

Uses the display as the light source.

### Paint

Draw with a finger and save the drawing.

**Interface** Implemented · **Data** Live

Touch drawing works on the prototype, and drawings save to on-device storage.

### Morse Studio

Compose Morse code and send it as light, sound, infrared or vibration.

**Interface** Implemented · **Data** On-device

Playback through audio output is implemented. Infrared output needs the Optical module, and vibration is not implemented.

### Voice Recorder

Record and play back short clips.

**Interface** Specified, deferred · **Data** —

Not currently implemented. The launcher tile is disabled.
