**You build User Apps.** Write C, compile it to WebAssembly with the ORION SDK, install it over USB,
and it appears in the launcher beside the built-in applications — sandboxed, capability-gated, and
unable to take the device down.

## What a User App gets

An app declares the capabilities it needs and can use nothing else:

| Capability | What it gives you |
|---|---|
| `system` | Lifecycle, time since start, a developer log, redraw requests |
| `display` | Clear, filled rectangles and one line of text on the 280 × 240 panel, in the ORION palette |
| `input` | Tap and swipe gestures |
| `motion` | The latest acceleration and tilt sample |
| `storage` | A private key/value store that survives restarts |

Calling into a capability you did not declare fails the build, and ORION refuses such a package at
install. Everything else — drivers, buses, the file system, MissionOS screens and data, other apps,
the network — is outside the boundary by design.

## The workflow

<Steps>
  <Step title="Write">
    C, against `<orion/orion.h>`. Four lifecycle callbacks; two are required.
  </Step>
  <Step title="Build">
    `orion build` compiles, validates and packages the app into a single `.orionapp` file.
  </Step>
  <Step title="Install">
    `orion install` sends it over USB. ORION validates it again before activating it.
  </Step>
  <Step title="Run">
    It appears in the launcher's User Apps tab. Swipe from the left edge to leave it.
  </Step>
</Steps>
